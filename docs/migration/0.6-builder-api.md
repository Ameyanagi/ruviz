# Migrating to the 0.6 builder API

0.6 makes every plot type take the same shape. Before, four of ruviz's nineteen
series methods behaved differently from the other fifteen: they took a positional
`Option<Config>`, returned a different builder type, and silently lacked ~60
configuration methods their siblings had. That is gone.

Everything here is mechanical. There is one rule per change, and no behaviour
changes except where called out under [Behaviour changes](#behaviour-changes).

## The one entry point

```rust,ignore,reason=abridged-migration-snippet
Plot::new()
    .<series>(<data>)   // line, scatter, bar, histogram, boxplot, heatmap, ...
    .<setters>()        // series style, series config, plot-level settings
    .save("out.png")?;  // or .render(), .render_to_svg(), .save_pdf(), ...
```

**Every** series method on `Plot` uses exactly this chain, returns
`PlotBuilder<C>`, and accepts the same plot-level setters. There is no second
shape to learn and no exceptions to remember. When 0.6 landed there were 19 —
`line`, `scatter`, `bar`, `histogram`, `boxplot`, `boxen`, `violin`, `kde`,
`ecdf`, `heatmap`, `contour`, `area`, `step`, `stem`, `error_bars`, `pie`,
`radar`, `polar_line`, `quiver` — and every method added since joins the same
chain. The current list is in the
[ruviz::plots module docs](https://docs.rs/ruviz/latest/ruviz/plots/), which a
test keeps in step with the builder.

Eight more joined it in this release — `rug`, `strip`, `swarm`, `hexbin`,
`dendrogram`, `grouped_bar`, `stacked_bar` and `stacked_area` — bringing the
list to 29. They are additive: nothing that compiled before changes shape.

The last three take N named value columns over one shared axis
(`.grouped_bar(&categories, &[("Q1", &q1), ("Q2", &q2)])`) and push one ordinary
series per column, so each column gets its own palette colour and legend entry
and the chain itself is unchanged.

Joint plots and pair plots are now drawn by `plots::composite::{jointplot,
pairplot}`, which return a `SubplotFigure` — the same figure type `subplots`
returns — rather than a `PlotBuilder`.

Two families still have a public config but no builder method — 2D KDE and
regression/residual plots — so `Plot::new().regplot(..)` does not exist. They
are tracked in `docs/roadmaps/ruviz-audit-remediation-plan.md` and are not part
of this migration.

## 1. `histogram` / `boxplot` / `heatmap` lost their config argument

The positional `Option<Config>` is gone. Configure through the builder instead —
the same way `kde`, `violin`, `contour` and the rest have always worked.

| Before | After |
| --- | --- |
| `.histogram(&d, None)` | `.histogram(&d)` |
| `.histogram(&d, Some(cfg))` | `.histogram_with(&d, cfg)` |
| `.histogram_source(v, None)` | `.histogram_source(v)` |
| `.histogram_source(v, Some(cfg))` | `.histogram_source_with(v, cfg)` |
| `.boxplot(&d, None)` | `.boxplot(&d)` |
| `.boxplot(&d, Some(cfg))` | `.boxplot_with(&d, cfg)` |
| `.boxplot_source(v, None)` | `.boxplot_source(v)` |
| `.boxplot_source(v, Some(cfg))` | `.boxplot_source_with(v, cfg)` |
| `.heatmap(&grid, None)` | `.heatmap(&grid)` |
| `.heatmap(&grid, Some(cfg))` | `.heatmap_with(&grid, cfg)` |

The rule is the same every time: `None` — drop the argument; `Some(cfg)` — add
`_with` to the method name and unwrap the `Some`.

This is an arity change under an unchanged name, so it cannot be shimmed with
`#[deprecated]` — Rust has no overloading. It is the one hard break in 0.6.

Prefer the builder setters over `_with` in new code. Every knob on
`HistogramConfig`, `BoxPlotConfig`, `HeatmapConfig` and `ErrorBarConfig` has a
matching setter on the builder:

```rust,ignore,reason=abridged-migration-snippet
// Before
Plot::new()
    .histogram(&data, Some(HistogramConfig::new().bins(30).density(true)))
    .save("hist.png")?;

// After — preferred
Plot::new()
    .histogram(&data)
    .bins(30)
    .density(true)
    .save("hist.png")?;

// After — mechanical, when you already hold a config value
Plot::new()
    .histogram_with(&data, HistogramConfig::new().bins(30).density(true))
    .save("hist.png")?;
```

Four config knobs are spelled differently on the builder, because the generic
builder already owns those names for the series as a whole:

| Config setter | Builder setter |
| --- | --- |
| `HeatmapConfig::annotate` | `.annotate_cells()` (`.annotate()` takes an `Annotation`) |
| `HeatmapConfig::alpha` | `.heatmap_alpha()` (`.alpha()` sets the series alpha) |
| `ErrorBarConfig::color` | `.error_color()` |
| `ErrorBarConfig::line_width` | `.error_line_width()` |
| `ErrorBarConfig::alpha` | `.error_alpha()` |

The config types' own setters are unchanged: `HeatmapConfig::new().annotate(true)`
still reads exactly the same.

## 2. `PlotSeriesBuilder` is gone

`histogram`, `boxplot`, `heatmap`, the four `error_bars*` methods and the two
`*_streaming` methods used to return `PlotSeriesBuilder`. They now return
`PlotBuilder<C>` like every other series method:

| Method | Now returns |
| --- | --- |
| `histogram`, `histogram_with`, `histogram_source`, `histogram_source_with` | `PlotBuilder<HistogramConfig>` |
| `boxplot`, `boxplot_with`, `boxplot_source`, `boxplot_source_with` | `PlotBuilder<BoxPlotConfig>` |
| `heatmap`, `heatmap_with` | `PlotBuilder<HeatmapConfig>` |
| `error_bars`, `error_bars_source`, `error_bars_xy`, `error_bars_xy_source` | `PlotBuilder<ErrorBarConfig>` |
| `line_streaming` | `PlotBuilder<LineConfig>` |
| `scatter_streaming` | `PlotBuilder<ScatterConfig>` |

`PlotSeriesBuilder` and its `Deref<Target = Plot>` are deleted. If you named the
type in a `let` binding or a function signature, name `PlotBuilder<C>` (or take
`impl IntoPlot`) instead. Nothing else about the chain changes — `.into()`,
`.into_plot()`, `.end_series()`, `.save()` and every plot-level setter still work.

Two method names on those types changed to the spelling the other fifteen types
already used:

| Before | After |
| --- | --- |
| `.width(w)` | `.line_width(w)` |
| `.width_source(w)` | `.line_width_source(w)` |
| `.style(s)` | `.line_style(s)` |
| `.style_source(s)` | `.line_style_source(s)` |
| `.title_signal(t)` | `.title(t)` |
| `.xlabel_signal(t)` | `.xlabel(t)` |
| `.ylabel_signal(t)` | `.ylabel(t)` |

The `*_signal` methods were byte-identical to the plain ones — both take
`impl Into<PlotText>` and both accept a reactive source — so dropping the suffix
is the whole migration. `Plot::title_signal` and friends still exist.

### What you gain

`histogram`, `boxplot`, `heatmap` and `error_bars` now accept the ~60 setters
that were previously `PlotBuilder<C>`-only, including `.theme()`, `.legend_best()`,
`.size_px()`, `.ticks_all_sides()`, `.xscale()`, `.yscale()` and `.auto_optimize()`.

```rust,ignore,reason=abridged-migration-snippet
// Did not compile before 0.6 (E0507 through PlotSeriesBuilder's Deref)
Plot::new()
    .histogram(&data)
    .theme(Theme::publication())
    .legend_best()
    .save("hist.png")?;
```

Error bars gained inline configuration for the same reason:

```rust,ignore,reason=abridged-migration-snippet
// Before
Plot::new()
    .error_bars(&x, &y, &yerr)
    .error_config(ErrorBarConfig::new().cap_size(6.0))
    .save("err.png")?;

// After
Plot::new()
    .error_bars(&x, &y, &yerr)
    .cap_size(6.0)
    .save("err.png")?;
```

## 3. Deprecated names on `PlotBuilder<C>`

These still compile; they emit a deprecation warning and delegate to the new
name, so behaviour is unchanged.

| Deprecated | Replacement | Why |
| --- | --- | --- |
| `PlotBuilder<ViolinConfig>::width` | `violin_width` | `width` meant three different things |
| `PlotBuilder<BoxenConfig>::width` | `box_width` | " |
| `PlotBuilder<QuiverConfig>::width` | `arrow_width` | " |
| `PlotBuilder<QuiverConfig>::scale` | `arrow_scale` | read as an axis-scale setter next to `xscale`/`yscale` |
| `PlotBuilder<QuiverConfig>::headlength` | `arrow_head_length` | one coherent `arrow_*` family |
| `PlotBuilder<QuiverConfig>::headwidth` | `arrow_head_width` | " |
| `PlotBuilder<LineConfig>::style` | `line_style` | pure alias |
| `PlotBuilder<LineConfig>::style_source` | `line_style_source` | pure alias |
| `PlotBuilder<KdeConfig>::kde_line_width` | `line_width` | one spelling, honoured by every backend |
| `PlotBuilder<EcdfConfig>::ecdf_line_width` | `line_width` | " |
| `PlotBuilder<ContourConfig>::contour_line_width` | `line_width` | " |
| `PlotBuilder<PieConfig>::font_size` | `label_font_size` | shadowed the plot-wide `Plot::font_size` |
| `PlotBuilder<RadarConfig>::with_color` | `series_color` | matches its neighbour `series_label` |
| `PlotBuilder<RadarConfig>::with_fill_alpha` | `series_fill_alpha` | " |
| `PlotBuilder<RadarConfig>::with_line_width` | `series_line_width` | " |

## 4. `bandwidth` means one thing

KDE and violin plots both do kernel density estimation, but `bandwidth` took a
different argument type on each: `f64` on `PlotBuilder<KdeConfig>` and
`BandwidthMethod` on `PlotBuilder<ViolinConfig>`. Both now take
`impl Into<BandwidthMethod>`, so both accept both spellings:

```rust,ignore,reason=abridged-migration-snippet
Plot::new().kde(&data).bandwidth(0.5).save("kde.png")?;                     // fixed
Plot::new().kde(&data).bandwidth(BandwidthMethod::Silverman).save("k.png")?; // rule
Plot::new().violin(&data).bandwidth(0.5).save("violin.png")?;              // now works
```

`KdeConfig::bandwidth` changed type from `Option<f64>` to `BandwidthMethod`
(`None` was Scott's rule; the default is now `BandwidthMethod::Scott`, which
resolves to the identical value). If you read or wrote that field directly,
match on the enum. Every `.bandwidth(x)` call site keeps compiling.

KDE gained Silverman's rule as a side effect — it was previously reachable only
from violin plots.

## 5. Deprecated entry points

There is now one way to draw a plot. The alternatives still work and warn.

| Deprecated | Replacement |
| --- | --- |
| `ruviz::line(&x, &y)` | `Plot::new().line(&x, &y)` |
| `ruviz::scatter(&x, &y)` | `Plot::new().scatter(&x, &y)` |
| `ruviz::bar(&cats, &vals)` | `Plot::new().bar(&cats, &vals)` |
| `simple::line_plot(&x, &y, path)` | `Plot::new().line(&x, &y).save(path)` |
| `simple::line_plot_with_title(&x, &y, t, path)` | `Plot::new().line(&x, &y).title(t).save(path)` |
| `simple::scatter_plot`, `simple::bar_chart`, `simple::histogram`, and the `*_with_title` variants | the same chain with the matching series method |
| `.end_series()` before a terminal call | drop it — `save`/`render` finalize the pending series |

`.end_series()` is still the way to get a `Plot` value out of a chain (for
`subplots`, for example); it is only redundant immediately before `save`,
`render`, `.into()` or `.into_plot()`.

## Behaviour changes

These are deliberate, and they are the only places output can differ.

- **`legend_position` returns `Self`, not `Plot`.** The chain continues after it,
  so a following `.label(..)` now applies to the in-flight series instead of
  being dropped. If you bound the result as a `Plot`, add `.into_plot()`.
- **`ContourInterpolation::default()` is `Linear`, was `Nearest`.**
  `ContourConfig::default()` already used `Linear`, so an unconfigured contour
  plot is unchanged; only an explicit `ContourInterpolation::default()` moves.
- **`kde_line_width` / `ecdf_line_width` / `contour_line_width` under
  `--features parallel`.** The parallel backend ignored those knobs and drew a
  hardcoded 2.0pt stroke. `line_width` works on every backend, so switching to it
  can change the rendered stroke width — that is the bug being fixed.
- **`error_bars` seeds a default `ErrorBarConfig`.** A bare `error_bars` series
  now carries `Some(ErrorBarConfig::default())` rather than `None`. Every
  consumer already did `unwrap_or_default()`, so rendering is unchanged; only
  code asserting `error_config.is_none()` is affected.
- **Histogram binning and heatmap colour mapping run at finalize time.** They
  used to run inside the `histogram()`/`heatmap()` call. For a caller who never
  touches the builder the result is identical, but an ingestion error for bad
  data is now recorded later in the chain.

## New `Default` impls

Public config enums that had no `Default`, or whose `Default` disagreed with the
config that uses them, now follow one rule: `SomeConfig::default().field ==
FieldEnum::default()`. Affected: `BinMethod` (`Sturges` — the doc comment marking
`Uniform` as the default was simply wrong), `OutlierMethod`, `BoxOrientation`,
`WhiskerMethod`, `BandwidthMethod`, `ViolinScale`, violin `Orientation`,
`BoxenOrientation`, `StepWhere`, `StemMarker`, `StemOrientation`,
`ReduceFunction`, `AreaInterpolation`, `StackBaseline`, `ErrorLineStyle`,
categorical `BarOrientation`, `StripOrientation`, `SwarmOrientation`,
`JointKind`, `DiagKind`, `OffDiagKind`, `DendrogramOrientation`, `EcdfStat`,
`QuiverPivot` and `ContourInterpolation`.
